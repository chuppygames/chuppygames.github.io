# Day 010「深海クラゲとり」投稿メモ

---

## 1. リール撮影の秒割り(18〜20秒めやす)

| 秒数 | 映すもの | ねらい |
|---|---|---|
| 0〜2秒 | 「だいせいこう」演出のクライマックス(バナー「深海が輝いた！」+ 光の爆発) | 一番派手な瞬間を頭に。無音・2秒判断に勝つのはここだけ |
| 2〜5秒 | スタート画面 →「はじめる」タップ | 何のゲームか一瞬で伝わる導入 |
| 5〜14秒 | 実プレイ(速いクラゲをタップ連打、画面の半分以上を占める赤・紫の毒クラゲを避ける場面を必ず入れる) | 「速い」「まちがえやすい」がひと目で伝わる場面を選ぶ |
| 14〜18秒 | 結果画面(スコア + 「だいせいこう」の文字) | 数字で締めて「自分もやってみたい」を作る |
| 18〜20秒 | 「もう一度あそぶ」タップ(ループ導線) | 頭の2秒に自然につながるようループ編集 |

**撮り方のコツ**
- 縦向きで撮る
- 演出が出るまで粘って撮り、「だいせいこう」の瞬間だけ抜き出してあとから頭に移動する(撮影順と公開順は別でOK)
- 無音でOK。文字入れは最小限に(タイトルは動画に入れず、キャプション側に任せる)
- 毒クラゲ(赤・むらさき)が画面を埋めているカットを選ぶと、タップの緊張感が伝わりやすい

## 2. キャプション

**案A(素直・親しみ)**

```
Day 010は「深海クラゲとり」。

深海に浮かぶクラゲを30びょうでタップして集めるゲームです。
でもクラゲは速いし、画面の半分以上が毒クラゲ(赤・むらさき)。
9匹ぶん集めると「だいせいこう」の光の演出が出ます。

今日わかったこと:
お祝いの演出、結果画面より先に見せないと誰の目にも入らないんですね。
最初の実装だと演出が結果画面の下に完全に隠れてて、一回も見えてませんでした…。

AIとゲームを1本ずつ作って、プログラミング初心者なりに毎日わかったことを記録しています。
遊べます、プロフィールのリンクからどうぞ。
```

**案B(フック強め)**

```
「作った演出、一回も表示されてませんでした」

Day 010「深海クラゲとり」を作っていて気づいた話。
9匹集めると出るはずの「だいせいこう」演出、結果画面がすぐ上に覆いかぶさって毎回一瞬で消えてました。
表示の順番を直すだけで解決。地味だけど効きました。

ゲーム自体は光るクラゲをタップするだけ。ただし画面の半分以上は毒クラゲなので、勢いでタップすると普通に事故ります。
AIで毎日ゲームを作る記録、プロフィールから遊べます。
```

**この形式で必ず入れているもの**
- Day 010 とゲーム名
- 遊ぶ理由になる条件(9匹で「だいせいこう」演出)
- 今日わかったこと(専門用語なし)
- プロフィールへの導線

1行目がフィードで最初に見える部分なので、案Bを使うならそのまま1行目を活かす。

## 4. 投稿の設定

## 5. 次回への申し送り

- 最初は「指でなぞって複数のクラゲをまとめて集める」操作を試作したが、シンプルなタップの方が合うという判断で見送った。代わりに、クラゲの速度を上げて毒クラゲの比率を全体の半分以上(約57%)にすることで、タップそのものに緊張感を持たせる方向に振った。同じ「もの足りない」という課題でも、操作を増やす以外に難易度側で解決する道があるとわかったのは収穫。
- 上記の変更で「ふつう」プレイヤーの到達率は、小成功が約50%、だいせいこうが約26%(いずれもモンテカルロ10〜20万試行で再計算)。上手い人はほぼ毎回だいせいこうに届く一方、苦手な人はほぼ0点になる設計。次回、苦手層にも小さな手応えを残す仕組み(参加賞的な演出など)を検討したい。
- 演出まわりで「結果画面が演出を隠す」という表示タイミングのバグを本番直前に発見(z-indexではなく、表示の順番の問題)。今後、達成演出を入れる日は「演出→結果画面」の順で必ずタイマーを分けて設計する。
- 今回は物理演算(落下・反発)を使わない回だった。次は物理演算系のネタに戻すのもよさそう。
